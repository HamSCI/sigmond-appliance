SIGMOND APPLIANCE @@VERSION@@ — QUICK START
===========================================
You have a USB stick and a small computer with a radio receiver attached.
About an hour from now the machine will be recording HF time signals on its
own.  Read section 0 before you touch anything — it is the only part that
needs preparation.  (Everything here was read from this image's own code.)

⚠ INSTALLING ERASES THE MACHINE'S INTERNAL DISK, with no further warning
  once you boot from the stick.  Use a machine you mean to dedicate to this.


0. COLLECT THESE FIRST
----------------------
The wizard (step 5) asks for these, in this order.  Written down, that step
takes two minutes instead of twenty.  Only the first two are required.

  Reporter ID             REQUIRED   e.g. AC0G/B4
        Your callsign.  A suffix after the slash distinguishes several
        stations you run.
  Grid square             REQUIRED   e.g. EM38ww
        NOT ASKED AT ALL if the GPS clock already has a fix.
  Antenna description                e.g. 40 m dipole at 10 m
  Wi-Fi network + passphrase
        Only if you will run without a network cable.  Asked only when
        the machine has a Wi-Fi radio.
  DASI unit number                   e.g. 3  (for DASI-003)
        HamSCI DASI stations only; the wizard first asks whether this is one.
  Remote access                      Y (the default)
        Lets your fleet admin reach the station for support.
  PSWS station ID                    e.g. S000123   (S + six digits)
        From your account at https://pswsnetwork.eng.ua.edu/
  GRAPE instrument ID                e.g. 172
        The receiver, as numbered on the PSWS portal.
  Magnetometer instrument no.        e.g. 84
        Only if you have one.  It reports under the SAME station ID as the
        receiver — there is no separate magnetometer station ID.
  Status heartbeats                  Y (press Enter to accept the collector)
  Station designator                 e.g. AC0G-B4
        Offered from your reporter ID; press Enter to accept.

  No PSWS account yet?  Press Enter past those and carry on — the station
  records and works.  Add them later with:  sigmond-setup --reconfigure
  The upload KEY is a separate step done afterwards over SSH; the VM's
  login banner walks you through it.

Physically, before you begin:
  - A machine with an internal NVMe drive.  The installer writes ONLY to
    an NVMe drive.
  - The receiver (RX888) and GPS clock (LBE-1421) PLUGGED IN AND POWERED,
    before first boot.  A magnetometer or a TS-1 time injector plugs in now
    too.  Anything missing does NOT stop the install; add it later.
  - A USB stick of 16 GB or more.  It gets overwritten.
  - A screen and keyboard on the machine, until the wizard finishes.
  - A network: a cable to your router (the machine gets its address
    automatically), or a Wi-Fi network you join in the wizard.  IPv6-only
    sites work too.


1. WRITE THE STICK
------------------
The image is published UNCOMPRESSED — nothing to decompress, just write it.
Check the download first, with the image and its .sha256 in one folder:
    sha256sum -c sigmond-appliance-@@VERSION@@-*.sha256

  BEST: the flasher from the sigmond-appliance repo.  It finds the stick by
  its removable+USB attributes instead of a letter you type, REFUSES the
  disk carrying the running system, and reads the stick back to compare
  hashes:
    ./flash-usb.sh sigmond-appliance-@@VERSION@@-*.img

  By hand, if you have only the image:
    sudo dd if=sigmond-appliance-@@VERSION@@-*.img of=/dev/sdX bs=4M \
            oflag=direct conv=fsync status=progress
    sync

  ⚠ /dev/sdX is YOUR job to get right, and getting it wrong overwrites that
  machine's own disk with no further prompt.  Confirm the target is the
  stick — size, and that it is removable — before you press enter:
    lsblk -dno NAME,SIZE,TRAN,RM,MODEL

  Then VERIFY by reading the stick back and comparing hashes — read EXACTLY
  the image's byte count, which flash-usb.sh does for you:
    IMG=sigmond-appliance-@@VERSION@@-*.img
    sudo head -c "$(stat -c %s $IMG)" /dev/sdX | sha256sum
    sha256sum $IMG
  The two hashes must match.  (A `dd ... count=N` written in whole 4 MiB
  blocks silently reads SHORT whenever the image is not an exact multiple
  of the block size, and then mismatches on a perfectly good write.)

  ⚠ Do NOT verify with `file -s /dev/sdX`.  It reads the boot sector only,
  so it happily says "DOS/MBR boot sector" for a stick that took the first
  megabyte and then fell off the bus, and for a stick still carrying last
  month's image.


2. BOOT FROM THE STICK
----------------------
With the receiver already connected, boot the machine from the USB.
Proxmox VE installs AUTOMATICALLY.  This is where the internal disk is
erased.


3. WAIT FOR IT TO SWITCH ITSELF OFF (~3 min)
--------------------------------------------
That is not a failure — it is the signal.
    REMOVE THE USB STICK, then power the machine back on.
The power-off is deliberate: some firmwares always boot USB first and would
otherwise install again in a loop.


4. PUT THE STICK BACK WHEN ASKED
--------------------------------
The machine now starts from its own disk.  When the console says
    NEXT STEP: plug in the Sigmond install USB stick.
insert the SAME stick again, in any port, and leave it in.  The console
answers "Importing the decoder VM (~3 min). LEAVE THE STICK IN."
The decoder VM (VMID 100) imports automatically (~3 min), sized to this
machine (all CPUs minus one pair, RAM minus 2 GB).


5. ANSWER THE WIZARD  (LEAVE THE STICK IN)
------------------------------------------
First the wizard lists the equipment it found (RX888, GPSDO, TS-1, RM3100).
Missing items do not stop it.  Then it asks the questions from section 0,
in that order:

   1) Reporter ID — your callsign
   2) Grid square (skipped when the GPS clock has a fix)
   3) Antenna description (or Enter to skip)
   4) Wi-Fi — only on a machine with a Wi-Fi radio; Enter skips
   5) Is this a DASI station, and its unit number
   6) Enable remote access?  [Y/n]
   7) PSWS station ID, then the GRAPE and magnetometer numbers
   8) Send status heartbeats?  [Y/n] — press Enter to accept
   9) Station designator — press Enter to accept the suggestion

A REVIEW SCREEN then shows every answer: type a line number to change one,
or Y to apply.

The heartbeat question needs nothing from your sheet.  Saying yes lets a
dashboard show that your station is alive and healthy: a small report every
five minutes, outbound only, nothing listening on your machine.  The
collector it names can be changed later without reinstalling.

Got something wrong?  Rerun any time:  sigmond-setup --reconfigure


6. REMOVE THE STICK — IT POWERS OFF — POWER IT BACK ON
------------------------------------------------------
The host now tunes itself: CPU isolation + pinning (grub), USB controller
passthrough to the VM.  The console then says:
    >>> INSTALL COMPLETE — REMOVE THE USB STICK NOW <<<
    As soon as the stick is removed this machine POWERS OFF.
Pull the stick.  The machine switches OFF (it does not reboot).  Switch it
back on.  The full power-off also resets the RX888, which it needs.

While the console panel says STATION IS STILL BUILDING, leave it alone:
on a fresh machine that can take tens of minutes.


7. THINGS THAT LOOK WRONG AND ARE NOT
-------------------------------------
  The machine switches itself off — TWICE
        Both expected: after the first install (step 3) and after you
        remove the stick at the end (step 6).  Power it on each time.
  It asks for the stick a SECOND time
        Expected — the first boot installs the system, the second loads
        the recorder.
  The keyboard stops working at the end
        Normal.  The USB controllers now belong to the VM; the panel says
        the console is read-only.  Use ssh or a web page from another
        computer.
  "no RX888" or other missing equipment
        The station installs and waits.  Plug the device in, then on the
        VM:  smd status   and   smd adopt <name>.  Nothing starts until
        you ask.
  Remote access says FAILED
        The support server may be busy.  Turn it on later with
        sigmond-setup --reconfigure
  "INSTALL CANNOT CONTINUE NORMALLY: ..."
        No working network.  The title says which case (no cable detected /
        port connected but nothing answered / no address offered), and the
        block lists three ways out: move the cable to a port with a link
        light and reboot; set a fixed address with
            sigmond-setnet 10.0.0.50/24 10.0.0.1
        or use Wi-Fi:  sigmond-wifi scan   then   sigmond-wifi join <network>


8. AFTERWARDS
-------------
The console panel lists every address and login with your real values.

  Proxmox web GUI   https://<host-ip>:8006
  Host login        ssh root@<host-ip>
  Decoder VM login  ssh sigmond@<vm-ip>   (also hamsci@)
                    or, through the host:  ssh -p 2222 sigmond@<host-ip>
  Live receiver     http://<host-ip>:8081
  Station pages     http://<host-ip>:8000
  Magnetometer      http://<host-ip>:8082

ONE PASSWORD for the whole station, starting as  hamsci-sigmond.  The
wizard copies the host's root password to the VM's sigmond, hamsci and root
accounts (root login over ssh stays off on the VM).  CHANGE IT: run
passwd on the host and in the VM.

PSWS: log in to the VM; its banner shows this machine's public upload key.
Paste it into the PSWS portal for your station, then run:  smd psws verify
ONE KEY SERVES THE WHOLE MACHINE: if it uploads for more than one station,
register the same key on each.

NO SPOTS OR PSWS DATA LEAVE YET: a new station starts with its site sink
switch at off.  It records and decodes but sends no data; only its heartbeat
goes out.
Log in to the VM, watch decode counts with  smd watch wspr  and  smd watch psk,
check reporter ID, callsign and grid, then run:  smd sink status
Any reason except  new station: ...  means someone set the switch on purpose:
ask your fleet admin.  If the reason reads  new station: ...  run:
    smd sink upload
From about 01:00 to about 04:00 UTC, while data packs, that command refuses;
run it again when packing ends.
(INSTALL.md section 9 has the details.)

This stick is appliance version @@VERSION@@.  Before the wizard runs, the
Proxmox host is named sigmond-appliance-@@VTAG@@ and the VM
sigmond-decoder-@@VTAG@@ (so you can tell which image a machine came from);
the wizard then renames them to your station designator — VM = designator
(e.g. AC0G-B4), Proxmox host = designator-PM (AC0G-B4-PM).  The image
version stays visible in /etc/sigmond-appliance/version and the login panel.

AFTER INSTALL — the operator guide (day-2 checks, troubleshooting, what not
to touch): https://github.com/HamSCI/sigmond/blob/main/docs/operator/README.md


9. RETURNING STATION?  (key restore)
------------------------------------
If this replaces an existing Sigmond station, its registered PSWS/upload
keys can ride the stick so no portal re-registration is needed:
  1. On the OLD station (or from a backup):
       tar czf site-keys.tar.gz -C / etc/hs-uploader/keys home/timestd/.ssh
  2. AFTER burning this stick, it shows one small FAT volume (the EFI
     partition) on any Mac/Windows/Linux machine — copy site-keys.tar.gz
     onto it and eject.
  3. Install normally.  The wizard restores the keys and runs the PSWS
     verify automatically.
